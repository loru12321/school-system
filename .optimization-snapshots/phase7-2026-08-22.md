## What Was Fixed

### Starter-Hub 3-Tier Layout Rendered Wrong Columns in Production
The redesigned starter hub (3-tier layout) rendered with phantom grid tracks:
`.starter-tier--primary` computed 6 columns instead of `1fr 1fr`, and the
entry grid rendered 3 columns instead of 2×2. Children carried computed
`grid-column: span 6`.

**Root cause**: a legacy block in `src/assets/css/workbench-design-language.css`
written for the old 12-column starter grid, with `!important` overrides:

```css
html body:not(.dark-mode) #app #starter-hub .starter-card--tasks,
html body:not(.dark-mode) #app #starter-hub .starter-card--entry { grid-column: span 6 !important; }
html body:not(.dark-mode) #app #starter-hub .starter-card--entry > div,
html body:not(.dark-mode) #app #starter-hub .starter-card--templates > div {
    grid-template-columns: repeat(3, minmax(0, 1fr)) !important;
}
```

The workbench file is bundled into the main style asset by Vite, so the stale
`!important` rules out-specified the new `1fr 1fr` layout in `main.css`. The
earlier CSS cleanup had removed the stale rules from `main.css` only — this
file was never audited.

## Fix
Removed the entire legacy 12-column override block from
`workbench-design-language.css` (the `.starter-grid`/`.starter-card` grid
spans, `.status-grid`, the 3-column entry override, and the stale `span 6`
rules inside the 1180px and 820px media queries). Kept the live rules in the
file (sidebar collapse behavior, analysis workspace layout).

Also removed the dead card-mosaic rules from `main.css` (`.starter-grid`,
old `.starter-card` box styles, `.status-grid`) — pure deletion, zero
calculation changes.
