## 项目结构与检查范围

项目采用 Vite 构建、原生 JavaScript 分模块运行时、Web Worker 计算、Cloudflare Worker + D1 网关，并保留 Supabase 相关迁移与历史集成。产品包含数据准备、联考评价、县域对标、教学改进、学生发展和教务执行，导航清单覆盖 31 个独立模块入口。现有测试对届别隔离、学校别名、教师范围、考试恢复、两率赋分和导出已建立较多约束。

本次检查了页面入口、模块清单、启动/加载链、计算 Worker 与既有计算测试、数据与权限测试、CSS 构建链、Service Worker 缓存、CI/发布配置。线上实际查看准备状态、综合评价、数据检查；本地执行全模块烟测。没有逐一操作生产的删除、导入、云端保存、改密等写入流程，也没有执行数据库迁移。通过源码与测试审查不能替代生产数据库权限审计或穷尽全部业务组合。

## 已修复与落实的优化项

1. **P1：CSS 去重破坏媒体查询和层叠作用域。** 原脚本用正则在整个样式表中删除相同规则，例如 `.x{color:red}@media(max-width:600px){.x{color:red}}` 会丢失桌面规则。改用 PostCSS 解析，仅删除同一父节点内紧邻且完全相同的规则。新增用例覆盖媒体查询、supports、layer、动画、字符串花括号和中间规则。位置：`scripts/build/dedupe-dist-css.mjs`。

2. **P1：CSS 清理遗漏运行时动态界面。** 原脚本只扫描入口 HTML，大量延迟加载模块在 JavaScript 中生成的 DOM 不在扫描范围。现递归扫描构建后的 `assets/js`；保留运行时可能使用的动画、字体和 CSS 变量，同时仍移除未引用的普通选择器。新增测试直接运行真实构建脚本，验证动态样式保留、无用选择器删除。位置：`scripts/build/purge-unused-css.mjs`。PurgeCSS 的 `keyframes/fontFace/variables: true` 实际表示启用删除，并非保留，已按[官方配置文档](https://purgecss.com/configuration)纠正。

3. **P1：过期构建检查漏掉主要源码。** 原检查只看根配置及 `src` 顶层文件，漏掉 `public/assets/js`、嵌套 CSS、构建处理脚本。现递归覆盖 `src`、`public`、`scripts/build`、`scripts/vendor`，并加入锁文件。新增真实文件时间测试，验证改动这些输入会阻止旧产物通过。位置：`scripts/check-dist-fresh.js`。该检查仍沿用时间戳及 5 秒宽限，尚不能识别删除文件或保留时间戳的内容替换。

4. **P2：当前年级与考试年级容易混淆。** 线上同屏出现“2024级 · 8年级”与“7年级”，来源分别是当前学年和历史考试，不能直接强行统一。工作区改为“考试：7年级”，并加入原生悬停说明；只改展示文字和提示，不改年级推断、届别、考试元数据或取数。位置：`public/assets/js/shell-runtime.js`。

5. **P1：增加不依赖云端的计算结果回归门禁。** 从起点提交的真实计算 Worker 冻结 36 组完整输出摘要，覆盖 6—9 年级、普通数据、空数据、单人、并列、零分、空分、乡镇范围、上线率开关及非核心学科。源码和压缩后的发布 Worker 均逐组比较；新增构建回归测试和该检查同时接入 `validate:build` 与 `check:release-fast`。位置：`scripts/test-calculation-output-invariance.js`、`scripts/fixtures/calculation-output-baseline.json`。摘要回归证明与原版本一致，不是重新认定现有业务口径正确。

## 仍需安排的优化项

6. **P1：Service Worker 缓存策略需要单独验证。** `public/sw.js` 中名为 network-first 的运行时/API函数存在先返回缓存再后台更新的分支；API 离线回退还会查缓存。建议补齐账号切换、撤销权限、断网及更新版本的行为测试，核对 `no-store` 与缓存分区，再修改策略。这会影响数据新鲜度和离线行为，本次没有将其混入计算结果保全修复。

7. **P1：桌面侧栏的键盘可达性。** `renderNavigation` 用带点击处理的 div 创建分类入口，线上可访问性树也将它们暴露为容器。建议迁移为原生按钮并验证 Tab、Enter、Space、焦点恢复及选中状态；需配合现有侧栏 CSS 检查外观。当前截图不构成全面无障碍合规结论。

8. **P1：真实浏览器回归对在线数据和默认登录配置依赖较强。** 现有计算快照依赖特定届别及真实数据，数据归档、账号变更或网络故障都会影响测试。建议逐步建设隔离的匿名固定数据集；本次增加的离线 36 组基线是第一步，仍保留现有云端快照检查。

9. **P2：样式层与大运行时模块继续拆分。** 现有 CSS 加载契约记录 21 层样式；`app.js`、分班和排课模块较大。建议按模块逐步清理覆盖关系和拆分副作用，逐步增加真实行为测试，避免一次性重写计算模块或粗暴删除“看似重复”的 CSS。

10. **P2：CSP 与测试质量。** 当前检查输出 47 个内联事件处理器、902 个内联样式，仍需 `unsafe-inline`；部分测试仅检查源码包含字符串。建议继续迁移事件委托，降低内联数量，并优先补充实际 DOM、缓存和发布脚本行为测试。

11. **P2：发布输入的内容校验。** 后续可增加构建输入清单/哈希，检测删除文件、时间戳未变化等情况，替代单纯依赖 mtime；同时避免把构建产生的版本文件算入循环依赖。

## 构建体积变化

恢复被误删的样式会增加体积。原提交的离线 `lt.html` 经 Brotli 11 压缩为 349,952 字节，修复构建约 360.5 KB，增加约 10.6 KB。离线压缩预算由 350,000 调整为 362,000，留下不足 1.5 KB 的波动空间；其余体积预算未放宽。此项是有依据的正确性取舍，不能描述为体积缩小。Web CSS 约 600.6 KiB，仍在原有 640,000 字节上限内。
