# 智能考场编排器重构设计

日期：2026-10-09  
状态：已由用户批准  
范围：教务执行 / 考场编排

## 1. 背景与目标

现有“智能考场编排器”只能读取工作簿的第一个 Sheet，按固定人数切分考场，并提供同班互斥和 S 型座位等开关。桌面 `考号及考场` 样例体现的是一套完整考务链路：多 Sheet 学生及成绩导入、排除名单核对、保留零分但参考学生、按成绩稳定排序、按考场容量连续分配、公开与保密输出分离，以及 Excel、考场门牌、桌签等成套文件生成。

本次重构采用四步式工作台：

1. 导入资料
2. 核对名单
3. 编排考场
4. 预览与输出

目标是让教务人员能从一个文件夹或若干 Excel 文件开始，在系统内完成数据识别、异常核对、考场生成、人工复核和成套文件下载。

## 2. 已确认的业务决策

1. 成绩属于保密数据，只用于后台排序和单独的保密导出。
2. 考场名单、班级通知表、门牌和桌签不显示总分或单科成绩。
3. 支持“选择文件夹自动识别”和“单独上传 Excel”两个入口。
4. 优先读取或维护“考场名称 + 容量”；没有考场配置时按计划考场数或单场上限自动均衡。
5. 只有明确列入排除名单的学生才不参加编排。
6. 零分、缺考记录或成绩缺失学生默认继续参加，在生成前单独提示确认。
7. 默认采用桌面样例口径：按总分降序，同分按原班级和源表顺序稳定排序，再按考场容量连续分配。
8. 当前同班互斥与 S 型排列移入高级规则，默认关闭，避免破坏严格排名顺序。

## 3. 参考样例还原结果

桌面样例 `新生分班方案.xlsx` 包含 337 名学生。明确排除 12 人后，共编排 325 人；其中 5 名总分为 0 或标记为未参加成绩考试的学生仍保留在考场编排中。

样例输出与以下稳定排序完全一致：

```text
总分降序 → 原班级升序 → 源 Sheet 内原序号升序
```

325 人被均衡分配到 6 个考场，人数分别为：

```text
55 / 54 / 54 / 54 / 54 / 54
```

考号从 `261580001` 连续递增，每个考场的座号从 1 重新编号。

样例输出包括：

- 考场考号总表
- 按班级分表
- 按考场分表
- 六页 A4 横向考场门牌
- 每个考场一份 A4 纵向桌签，每页 2 列 × 8 行

## 4. 信息架构

页面内部使用四步进度导航，顶部保留系统级考试、年级和云端状态信息。

### 4.1 页面顶部

展示：

- 考试名称
- 届别与年级
- 当前步骤
- 原始学生数
- 参考人数
- 排除人数
- 考场数
- 待处理异常数
- 最近生成时间与输出版本

### 4.2 工作区布局

- 左侧：当前步骤的输入、筛选和设置。
- 主区域：数据表、名单核对或考场结果预览。
- 右侧：人数统计、容量状态、异常摘要和规则说明。
- 底部固定操作栏：保存草稿、上一步、下一步、生成、重新生成或下载。

页面使用系统已有色彩、间距、圆角和 Tabler 图标规范。工作流状态使用蓝色、绿色、橙色和红色表达当前、完成、待确认和阻断状态。界面不使用表情图标。

## 5. 第一步：导入资料

### 5.1 导入入口

#### 选择文件夹

在支持 File System Access API 的 Chromium 浏览器中选择一个文件夹。系统只读取用户明确选择的目录及其可访问文件，并自动识别：

- 学生及成绩表
- 不参加考试名单
- 考场配置表
- 已有考务输出

无法使用目录选择能力时，界面自动保留多文件上传入口。

#### 上传 Excel

支持拖放或文件选择，可一次上传一个或多个 `.xlsx`、`.xls` 或 `.csv` 文件。

### 5.2 数据契约

#### 学生及成绩表

必需字段：

- 姓名
- 班级或现班级
- 总分

可选字段：

- 学号
- 性别
- 原班级
- 语文
- 数学
- 英语
- 其他学科
- 源序号

当总分为空且存在单科成绩时，可按已识别的数值型学科合计生成临时总分；系统必须将该行为标为待确认，不能静默替换原始总分。

#### 不参加考试名单

必需字段：

- 姓名
- 班级

可选字段：

- 学号
- 不参加原因
- 备注

#### 考场配置表

必需字段：

- 考场名称
- 容量

可选字段：

- 教学楼
- 教室
- 展示顺序
- 备注

### 5.3 多 Sheet 识别

系统读取所有可见 Sheet，并按表头结构识别用途。识别顺序为：

1. 明确包含“现班级”的学生表
2. 以当前班级命名且字段完整的学生表
3. 包含“原班级”的历史映射表
4. 排除名单与考场配置
5. 无法识别的其他 Sheet

同一学生在当前班级表和历史映射表中重复出现时，系统将其识别为同一候选记录，并在核对步骤展示字段来源。系统不得把映射表中的重复记录再次计入参考人数。

### 5.4 模板与字段映射

页面提供三种模板下载。无法自动识别表头时，用户可在映射面板中选择“姓名、班级、总分”等字段。映射结果在当前工作区内保存，用于重新导入同结构文件。

## 6. 第二步：核对名单

### 6.1 数据状态

学生记录被归入以下状态之一：

- 正常参考
- 明确不参加考试
- 零分或成绩缺失但仍参考
- 重复记录
- 缺少关键字段
- 排除名单未匹配
- 来源冲突

### 6.2 学生匹配

匹配优先级：

1. 学号
2. 姓名 + 当前班级
3. 姓名 + 原班级

同一匹配键对应多条记录时必须进入人工核对，不能自动合并。

### 6.3 排除规则

- 只有用户确认的排除名单会从编排集合移除。
- 零分、缺考、未参加成绩考试或总分缺失不等于不参加本次考试。
- 用户可将学生移入或移出排除名单，并填写原因。
- 排除与恢复操作记录操作者、时间和原因。
- 严重异常未处理时阻止生成；可解释的零分或缺失成绩只要求确认。

### 6.4 核对汇总

生成前必须显示：

```text
原始记录数
去重后学生数
排除人数
正常成绩参考人数
零分或缺失成绩参考人数
最终编排人数
```

## 7. 第三步：编排设置与算法

### 7.1 基础设置

- 考试名称
- 年级名称
- 考号前缀
- 流水号位数，默认 3 位
- 排名字段，默认总分
- 计划考场数或单场人数上限
- 考场名称及容量

### 7.2 默认排名算法

```text
有效数值总分降序
→ 原班级自然顺序
→ 源 Sheet 顺序
→ 源行号顺序
```

零分或缺失成绩学生排列在有效成绩学生之后，并继续使用相同的稳定次序。

排名结果必须可复现：同一批数据和同一组规则重复生成时，顺序和考号保持一致。

### 7.3 考场容量算法

有明确考场配置时：

1. 按考场展示顺序读取容量。
2. 按排名顺序连续填入各考场。
3. 最后一个使用的考场允许未满。
4. 容量总和不足时阻止生成，并显示缺少座位数。

只有计划考场数时：

1. 将最终编排人数除以考场数。
2. 余数优先分配给序号靠前的考场。
3. 各考场人数差不超过 1。

只有单场上限时：

1. 计算需要的最少考场数。
2. 在不超过上限的前提下均衡人数。

### 7.4 考号与座号

- 考号 = 前缀 + 补零后的全级连续流水号。
- 座号 = 当前考场内从 1 开始的连续序号。
- 考号、考场和座号组成唯一编排结果。
- 修改前缀、容量、名单或排序规则后，现有结果进入“需要重新生成”状态。

### 7.5 高级规则

以下规则默认关闭：

- 相邻座位同班规避
- S 型座位号
- 性别交错
- 指定学生固定考场或座位

开启高级规则时，系统必须提示该规则可能改变严格成绩顺序，并在结果中记录规则版本。

## 8. 第四步：结果预览与人工调整

### 8.1 全级排名视图

保密视图，显示：

- 全级名次
- 学号
- 姓名
- 性别
- 原班级与当前班级
- 总分及单科成绩
- 考场
- 座号
- 考号
- 数据状态

### 8.2 按考场视图

显示：

- 座号
- 考号
- 姓名
- 性别
- 原班级或当前班级

### 8.3 按班级视图

显示：

- 班内序号
- 姓名
- 性别
- 考场
- 座号
- 考号

### 8.4 学生查询

支持使用姓名、学号或考号查询考场和座号。重名时同时显示班级和学号供选择。

### 8.5 人工调整

允许交换两名学生或修改指定学生的考场和座号。每次调整后检查：

- 重复考号
- 重复座位
- 考场超容
- 考号断号
- 漏排学生
- 已排除学生误入结果

人工调整记录进入保密审计文件。

## 9. 输出设计

### 9.1 保密输出

#### `成绩排名及编排依据.xlsx`

工作表：

- 全级排名
- 分班成绩
- 编排依据
- 人工调整记录
- 规则与生成信息

包含名次、总分、各科成绩和编排结果。

#### `不参加考试及数据核对.xlsx`

工作表：

- 不参加考试名单
- 零分或缺失成绩但参考
- 重复与冲突
- 未匹配排除项
- 缺失字段

### 9.2 公开 Excel 输出

#### `考场考号总表.xlsx`

字段：

```text
序号 / 姓名 / 性别 / 原班级或当前班级 / 考场 / 座号 / 考号
```

#### `考场考号-按班级分表.xlsx`

每个班级一个 Sheet，字段：

```text
序号 / 姓名 / 性别 / 考场 / 座号 / 考号
```

#### `考场考号-按考场分表.xlsx`

每个考场一个 Sheet，字段：

```text
座号 / 考号 / 姓名 / 性别 / 原班级或当前班级
```

公开文件不得出现总分、单科成绩、排除原因或内部备注。

### 9.3 Word 打印输出

#### `考场标志.docx`

- 每个考场一页
- A4 横向
- 年级、考场名称、考号范围三行居中
- 页面可直接打印为门牌

#### `考号桌签-第X考场.docx`

- 每个考场一份文件
- A4 纵向
- 每页 2 列 × 8 行，共 16 张
- 考号使用醒目的红色大号字
- 显示姓名、考场和座号
- 保留裁切边框

### 9.4 一键打包

输出包结构：

```text
<考试名称>_考场编排_v<版本>.zip
├─ 01_保密资料
│  ├─ 成绩排名及编排依据.xlsx
│  └─ 不参加考试及数据核对.xlsx
├─ 02_班级通知
│  └─ 考场考号-按班级分表.xlsx
├─ 03_考场名单
│  ├─ 考场考号总表.xlsx
│  └─ 考场考号-按考场分表.xlsx
├─ 04_门牌
│  └─ 考场标志.docx
├─ 05_桌签
│  └─ 考号桌签-第X考场.docx
└─ 编排说明.txt
```

输出版本每次正式重新生成时递增。说明文件记录输入文件、最终人数、排除人数、考场容量、排序规则、生成时间和系统版本，不记录成绩明细。

## 10. 数据安全与保存

- Excel 和文件夹内容在浏览器本地解析。
- 原始成绩文件不自动上传云端。
- 只有用户主动保存时才记录编排配置和结果摘要。
- 保密输出与公开输出使用不同的数据投影和独立生成函数，避免公开文件误带成绩字段。
- 离开页面时，如果存在未保存的名单调整或未下载的正式结果，显示离开提醒。
- 提供“清空当前编排”操作，清除当前页面缓存和文件句柄。

## 11. 实现边界

- 复用系统现有 SheetJS 能力读取和生成 Excel。
- 新增独立的考场编排运行时模块，避免继续扩大通用 `app.js`。
- 页面结构放在现有教务执行模块内，保持顶部导航、侧栏和全局状态栏一致。
- 文件识别、数据规范化、编排算法、公开输出和保密输出采用独立函数边界。
- Word 输出使用可在当前前端构建链路中运行的文档生成能力，必须生成真实 `.docx` 文件。
- 本次不建设跨考试历史任务中心；当前工作区可以保存草稿，但历史版本管理属于后续范围。

## 12. 验收标准

### 12.1 样例数据验收

使用桌面 `考号及考场` 样例：

- 识别 337 名原始学生。
- 正确排除 12 人。
- 保留 5 名零分或未参加成绩考试但仍参考的学生。
- 最终编排 325 人。
- 默认得到 6 个考场，人数为 55、54、54、54、54、54。
- 排名顺序与样例总表一致。
- 考号从 `261580001` 到 `261580325` 连续生成。
- 每个考场座号从 1 连续编号。

### 12.2 数据安全验收

- 所有公开 Excel 和 Word 文件均不包含成绩字段。
- 保密排名文件包含完整排名依据。
- 排除名单和异常原因只出现在保密输出。

### 12.3 文件验收

- 三份公开 Excel 的 Sheet、表头、行数和排序正确。
- 考场门牌页数等于使用的考场数。
- 每个桌签文件页数和标签数量与考场人数一致。
- 一键打包文件结构完整，文件名可读，无重复或空文件。

### 12.4 交互验收

- 用户能在界面看到所有必需字段说明和模板入口。
- 重复、缺失字段、未匹配排除项和容量不足都有明确提示。
- 严重异常未解决时不能生成正式结果。
- 返回前一步修改数据后，旧结果明确显示为需要重新生成。
- 表格支持搜索、筛选、冻结表头，并在 500 名学生规模下保持可用。
