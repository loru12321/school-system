# 响应式登录页、云端存档与高级应用图标设计

## 目标

在不改变现有桌面端主题和业务流程的前提下，完成三项统一优化：

1. 手机和平板登录页不再发生上下区块遮挡，登录表单始终优先可见、可滚动、可操作。
2. “云端存档管理”表格能够稳定显示表头、记录、加载状态、空状态与错误状态。
3. Windows、Android、iOS 使用同一“知识绽放”母图标，并在应用服务模块中同时展示最新版与历史版本。

## 设计原则

- 延续现有系统的象牙白、雾蓝、柔和红色视觉语言，不重做桌面端整体主题。
- 把抖音收藏参考中的吸引力转译为明亮高光、修长比例、克制红色焦点和时尚留白，不直接使用人物或社交媒体元素。
- 视觉层级优先于装饰：先保证信息顺序、间距、对齐和可读性，再使用轻量材质与阴影。
- 所有操作保持原功能和数据契约，不新增与本次目标无关的页面或流程。

## 视觉系统

### 色彩与材质

- 基底：象牙白、暖白和浅雾蓝。
- 强调色：现有品牌柔和红色；仅用于主操作、关键状态和图标焦点。
- 辅助高光：极少量香槟色边缘光。
- 材质：轻量珍珠釉与磨砂玻璃感，避免深黑背景、厚重金属、塑料高光和玩具感。

### 应用图标

选用概念 3“知识绽放”：打开的书本向上生长为三组修长页片，负空间形成上升路径，红色菱形作为知识与数据焦点。

母图标只保留一个核心符号，不增加文字、字母、毕业帽、人物或平台标志。平台适配时保持符号比例、颜色和安全区一致，仅调整圆角、背景和输出规格。

设计参考文件：`docs/design-assets/app-icon-knowledge-bloom-reference.png`。

## 响应式登录页

### 桌面端（大于 960px）

- 保留现有左右两栏结构和桌面信息密度。
- 左侧继续承担品牌与教学数据叙事；右侧保留身份、届别、毕业生档案与登录操作。
- 不改变当前表单字段、角色切换、验证和跳转逻辑。

### 平板端（769px–960px）

- 使用 40% 品牌区 + 60% 表单区的真实双栏布局。
- 品牌区缩减为标志、标题、短文案和最多三项核心能力，不展示桌面端大面积装饰内容。
- 表单区成为主视觉，允许页面纵向自然滚动，不使用负边距叠放或绝对定位悬浮。
- 横屏与竖屏均保证主要登录按钮无需水平滚动即可操作。

### 手机端（不大于 768px）

- 使用单列文档流：紧凑品牌横幅、身份切换、账号密码、届别/档案入口、主按钮。
- 品牌横幅不设置固定高度，不与表单重叠；非必要介绍折叠或隐藏。
- 登录容器使用 `min-height: 100dvh` 与安全区内边距，整页只保留一个纵向滚动容器。
- 输入框最小字号 16px，交互控件最小触控高度 44px，主按钮始终完整显示。
- 键盘弹出后，聚焦字段与提交按钮仍能通过自然滚动到达。

### 布局根因与治理

现有登录样式存在多层媒体查询、绝对定位、负 `margin`、固定/最小高度以及重复 `!important` 覆盖。实现时将最终响应式规则集中到一个后置样式层，明确桌面、平板和手机三个断点；移动和平板禁止登录主区使用绝对定位和负边距叠放。

## 云端存档管理

### 表格容器

- 表格外层提供可计算的最小高度和最大高度，记录区使用单一内部纵向滚动。
- 表头保持可见，列宽在桌面端稳定；小屏幕允许横向滚动，不压缩到不可读。
- 不在表格本身设置会吞掉 `tbody` 的固定高度或错误 `overflow`。

### 状态

- 加载中：表体显示明确的加载行，不出现只有表头的空白框。
- 有数据：每条记录完整展示项目名、上传时间、数据大小和操作。
- 空数据：显示“暂无云端存档”与上传指引。
- 错误：显示可读错误信息和重试入口，不用空白代替失败。
- 筛选后为空与真正无数据使用不同提示。

### 数据与交互

- 保留 `#dm-cloud-table`、现有复选框、上传、删除和批量删除事件契约。
- 渲染完成后同步更新记录数量、占用空间和选择状态。
- 删除操作继续使用现有确认机制，失败时恢复可操作状态。

## 应用服务与版本历史

- Windows、Android、iOS 卡片统一使用“知识绽放”图标。
- 每个平台优先展示最新版：版本号、发布日期、状态、文件大小和主要操作。
- 历史版本按平台分组并按发布日期倒序排列，明确 Beta、稳定版、待签名或不可下载状态。
- 继续读取现有发布清单与历史记录，不破坏当前免费下载链路。
- Windows 输出 `.ico` 所需尺寸，Android 输出 adaptive icon 前景/背景与常用 PNG，iOS 输出 AppIcon 资源集；最终构建计划中列出自动派生与校验步骤。

## 无障碍与兼容性

- 文本和控件对比度满足常规可读性要求。
- 键盘焦点可见；表单、标签页、下载和删除操作均可使用键盘访问。
- 覆盖手机、平板和桌面常见视口；同时检查横屏、竖屏、安全区和软键盘场景。
- 尊重 `prefers-reduced-motion`，不为图标或登录页添加强制大幅动画。

## 验证与验收

### 登录页

- 390×844、430×932、768×1024、834×1194、1440×1024 视口无重叠、裁切或水平溢出。
- 角色切换、输入、届别选择、毕业生档案查询和登录提交均可用。
- 登录按钮响应时间与网络请求耗时分别记录，避免把后端延迟误判为界面卡顿。

### 云端存档

- 分别验证加载、有数据、无数据、筛选为空、请求失败和大量记录场景。
- 表头、首条和末条记录均可访问；滚动不会让外层页面失去控制。
- 单删与批删的数量、占用空间和列表状态一致。

### 图标与版本中心

- 验证 16px、24px、48px、128px、512px 和 1024px 显示效果。
- 校验各平台清单中的版本号、文件名、字节数、发布日期和 SHA-256。
- 最新版与历史版本排序正确，缺少安装包时不得展示虚假下载按钮。

### 回归、发布与回滚

- 运行现有计算、发布清单、下载、登录和生产冒烟测试。
- 本地视觉验证通过后提交 GitHub，再部署 Cloudflare。
- 部署后复测生产域名的登录、云端存档和版本中心。
- 若生产验证失败，保留当前可用 Worker 版本并回滚，不覆盖现有可下载版本。

## 非目标

- 不重新设计桌面端全部页面。
- 不改变认证、云端存档或发布清单的数据模型，除非实现阶段发现必须修复的兼容问题。
- 不伪造 iOS TestFlight/App Store 状态或未签名安装包。
- 不引入付费托管、付费存储或新的商业依赖。
